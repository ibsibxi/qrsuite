# 来龙去脉：原作、原型、v2

文档里出现过两个「v1」，长期混用，导致「11× 提速」听起来像是在说原作慢。这里把三层关系一次讲清。

---

## 一、三层血统

| 层 | 是什么 | 形态 | 引擎 | 预处理 | 早退 |
|---|---|---|---|---|---|
| **Rust 原作** | [ZapcoMan/QRCodeScanner](https://github.com/ZapcoMan/QRCodeScanner) 的 `src/main.rs`（单文件 CLI），产物 `QRCodeScanner.exe` | 交互式（只从 `stdin` 读一行，逗号分隔多个路径） | **bardecoder 单引擎，只解 QR** | 10 个变体：原始 / 灰度 / 对比度×2 / 二值化 128·64·192 / 高斯模糊+二值化 / 锐化 / 反色 / 放大 2×（Lanczos3）；失败再试 4 个角落裁剪 | **有**——`decode_qrcode()` 一解出就 `return` |
| **Python 原型** | 重构中间态的单文件 `qrsuite.py`（**不在仓库里**，在本机旧目录） | 命令行，多引擎雏形 | zxing / cv2 / zbar | 18 个变体 | **无**——每张跑满 18 变体再汇总 |
| **本项目 v2** | `qrsuite/`（Python 包）+ `docs/`（纯前端站点）+ `android/`（原生 App） | 三形态 + 本地服务 | zxing-cpp / OpenCV / zbar / WeChatQRCode（可选）/ 原作 exe（可选）；浏览器 jsQR + ZXing-js；App ML Kit | Python 16～18 个变体（大图 16），浏览器另有清单 | **有**，且加了分辨率闸门与惰性引擎 |

**[BENCHMARK.md](BENCHMARK.md) 里那张「v1 vs v2」表的 v1 是第二行的 Python 原型**，判据很硬：13 张 × 18 变体
正好 = 表里的 234 阶段。Rust 原作只有 10+4 个变体、单引擎，而且本来就在命中后立刻返回，
所以那些数字（含「约 11×」）**不能**用来评价原作，原作也不按这个口径衡量。

## 二、原作做得好的地方，v2 保留了什么

- 原作的**级联思路**是对的：先试最便宜的原图，解出就走人。v2 沿用同一个思路，只是把它做成了
  可配置三档（`fast` / `balanced` / `deep`）并加了闸门。
- 原作的**预处理清单**（对比度、多阈值二值化、模糊+二值、反色、放大、四角裁剪）基本被 v2 吸收进
  `build_stages()`；v2 另外加了灰度复用、旋转、CLAHE、自适应阈值、中心裁剪。
- 原作的**日志文案**成了 v2 的一个隐式依赖：`OriginalEngine` 靠子进程 stdout 里的
  `二维码内容: ` 前缀取结果（`qrsuite/core.py` 的正则 ↔ 原作 `main.rs` 的日志语句）。
  **原作改日志格式，这个兼容引擎就会静默解不出任何东西**，详见
  [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。
- 原作自带的 8 个单元测试（URL 判定、预处理变体数、放大尺寸、空白图返回 None 等）在本仓库没有对应物；
  v2 这边是 `tests/smoke_test.py` + `tests/bench.py`，两边测试不通用。

## 三、v2 在原作基础上加了什么（以及为什么）

| 加了什么 | 为什么 |
|---|---|
| 命令行参数：路径 / 目录递归 / 通配符 / URL，多个输入 | 原作只读 `stdin`，没法脚本化、没法拖拽批处理 |
| 多引擎并联 + 结果按内容去重 | 单个解码器的盲区不重叠：低对比、旋转、局部损坏各有克星 |
| 一维码支持（Code128/39/93、EAN/UPC、ITF、Codabar、DataBar…） | 原作 bardecoder 只解 QR，一维码是 v2 净新增能力 |
| 纯前端静态站（零依赖、可离线、Worker 解码） | 让不懂命令行的人有个能发链接的入口 |
| 本地 Python 服务 + 网页「本机增强引擎」 | 网页端识别率不够时，在同一台机器上把强引擎并进来，且图片不出本机 |
| Android 原生 App（CameraX + ML Kit，显式移除网络权限） | 手机随手扫，且「图片不出设备」可被审计验证 |
| 结构化输出：JSON、退出码、统计（阶段数 / 引擎调用 / CPU / 是否早退） | 便于接入别的流程，也便于测量 |
| 结果缓存、惰性引擎、三档模式 | 默认路径要便宜；贵引擎只在需要时出场 |
| 原作的**跨平台限制**与速度都不是 v2 的主要动机 | 原作是单引擎 QR-only；v2 更像「顺手把能力铺开的二创」，是否值得这么多引擎/形态取决于使用者 |
